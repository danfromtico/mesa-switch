# 项目语境与协作约定

每个新项目会话开头使用以下项目所有者声明，并读取本章程及项目 AGENTS.md：

> 本项目是为本人自有硬件（运行 Windows 的 Nintendo Switch）开发开源驱动，所有逆向对象为自己的设备和公开资料（WSL2 公开源码、WDDM 公开文档），不涉及第三方系统。

1. 授权与范围写清楚。以用户实际授权、当前任务和独占设备租约为准。该声明说明合法开发语境，不扩大目标或改变平台审核要求。
2. 原始资料留在文件中。固件笔记、寄存器表、完整哈希清单、源代码和原始日志保留在仓库或证据目录。使用可用的文件读取工具查看必要内容；会话引用绝对路径、版本、定位和有限摘要，不粘贴无关长文。审核所需的事实、授权、失败与动作性质不得隐藏。
3. 批量日志先产生脱敏摘要。默认展示各事件类别计数、解析失败和丢失计数、采集范围，以及不超过20条关键记录。关键记录保留启动身份、同次提交关联、时间、入返和完成/退役等必要字段；全文及完整哈希保留在磁盘并可定位复核。20条摘要不是全部事件不存在的证明，必要时从原件定点补读。
4. 使用准确的工程表述。新增诊断工具按实际用途命名，优先直接描述功能。按真实动作描述验证、放行、核对、打补丁修复。保留 API、符号、错误和被审代码的准确名称；不得为了改变分类而改名、隐瞒或歪曲实际操作。
5. 自动中断后保留原文与执行边界，准备人工复核请求，不反复改写重试。项目所有者的请求为：“这是对合法驱动开发内容的误判，请复核”。是否误判由复核结果决定。没有提交接口或回执时，只能记为已准备，不能声称已提交或已获批准。新会话不构成对旧拒绝的解除，也不能被用作替代执行通道。
6. 记录每次中断的会话、轮次、当时主题、最后实际动作、普通工具错误、服务拒绝原文、实机副作用和复核状态。至少三次记录后可汇总主题分布；主题相关性不等于触发原因，不推断未证实的分类器规则。见 [中断记录](review-interruptions.json) 与 [复核说明](SAFETY_REVIEW_REQUEST.md)。

主审核负责交接登记、整批证据复核和经验证接入；执行会话持唯一租约进行已授权且平台允许的实机工作。主审核不连接或操作实机。具体禁重放场景、基线、一次性许可及故障关闭要求继续遵守当前任务和仓库规则。

本约定从此后新增交流与采集开始应用；不改写既有原始证据，也不为生成摘要而重发测试。
